\section{Overview of the Proposed System}
\label{sec:overview_of_the_proposed_system}

\hspace*{\parindent}KABISIG is a web-based, multi-tenant information system developed for the Sangguniang Kabataan (SK) councils of Naga City. It automates program management, youth registration and verification, budget and expense management, governance document and resolution handling, youth feedback, notifications, and reporting. Each of the 27 barangays operates as a separate tenant whose data is isolated by \texttt{tenant\_id} via PostgreSQL Row-Level Security (RLS), while the SK Federation President oversees tenant management, leadership transfer, and city-wide analytics. Role-based access control (RBAC) separates the responsibilities of the SK Chairperson, SK Officials (Kagawad, Secretary, Treasurer), and Youth constituents, and an audit log records actions across all roles. A public transparency dashboard presents budget summaries, program accomplishments, and announcements to citizens, supporting accountability in the use of SK funds in compliance with the DILG Full Public Disclosure (FPD) policy.

\section{Automated Functionalities}
\label{sec:automated_functionalities}

\hspace*{\parindent}The system provides rule-based automation to reduce manual record-keeping and support the operations of each SK council in the following areas:

\begin{itemize}
    \item \textbf{Youth Profiling and Demographic Classification:} Validates that a registrant’s age, computed from the birthdate on the registration form, is within 15 to 30 years. Assigns demographic classifications (Student, Out-of-School Youth, Scholar, PWD, Solo Parent, Employed, Unemployed) using deterministic if-then rules based on the registrant’s declared information. Computes a Youth Engagement Score from the youth’s program participation history.
    \item \textbf{Youth Verification and Digital Youth ID Provisioning:} Routes pending registrations to the SK Chairperson, who reviews the uploaded ID and approves or rejects the application. Upon approval, the system generates a unique Digital Youth ID with an embedded QR code.
    \item \textbf{Program Registration:} Allows only verified youth to register for programs, validates slot limits, and checks for scheduling conflicts.
    \item \textbf{QR Attendance Check-In:} Enables the Kagawad to scan Digital Youth ID QR codes through the device camera, records the check-in timestamp, and rejects duplicate entries.
    \item \textbf{Budget and Expense Monitoring:} Allows the Chairperson to set the annual SK budget in accordance with DILG JMC No. 1, s. 2025, and the Treasurer to allocate funds and record itemized expenses. The system computes line-item balances, utilization percentages, and applicable VAT and non-VAT tax withholdings, and sends alerts when expenditures exceed allocated limits.
    \item \textbf{Governance Document Routing and Compliance Tracking:} Allows the Secretary to upload resolutions, session minutes, vouchers, and liquidation reports and route them to the Chairperson for review and approval. The system tracks statutory submission deadlines, updates report statuses (Pending, Completed, Overdue), and sends reminders for pending approvals or missing requirements.
    \item \textbf{Rule-Based Feedback Classification:} Classifies feedback submitted through \textit{Boses ng Kabataan} (with an optional anonymity toggle that sets the user ID to NULL upon submission) as Positive, Neutral, or Negative using keyword-matching dictionaries, and summarizes frequently raised concerns and program requests for the Kagawad’s review.
    \item \textbf{Resolution and Legislative Tracking:} Generates sequential resolution numbers with validity periods, and records support, oppose, or abstain responses from verified youth on resolutions.
    \item \textbf{PDF Report Generation:} Compiles database records into standardized PDF documents client side via \texttt{jsPDF}, including accomplishment reports, attendance sheets, financial summaries, inventory forms, and audit documents formatted for COA submission.
    \item \textbf{Notifications and Social Media Posting:} Sends in-app event alerts, approval updates, and deadline reminders, and allows authorized SK officials to publish approved announcements to the council’s official Facebook Page through the Meta Graph API using encrypted page access tokens stored per tenant.
    \item \textbf{Multi-Tenant Administration and Federation Analytics:} Isolates each barangay’s data by \texttt{tenant\_id}. The SK Federation President manages administrative linkages via system invitation emails, processes leadership transfers, views aggregated city-wide analytics, and monitors the audit log across roles without directly managing individual barangay youth records.
    \item \textbf{Public Transparency Dashboard:} Presents authorized budget summaries, itemized expenditure tallies, completed program accomplishment reports, and announcements to unauthenticated citizens in read-only form.
\end{itemize}

\subsection{System Architecture}
\label{subsec:system_architecture}

\hspace*{\parindent}KABISIG follows a multi-tenant, three-tier architecture consisting of a presentation layer, an application layer, and a data layer. In the presentation layer, role-specific interfaces serve the SK Federation President, SK Chairperson, SK Officials (Kagawad, Secretary, Treasurer), Youth Constituents, and public viewers. The application layer enforces role-based access control and handles business rules, including youth verification, budget computations, document routing, and QR attendance. The data layer is a shared database managed through PostgreSQL with Row-Level Security (RLS), where every tenant-owned record carries a \texttt{tenant\_id} that scopes each query to a single barangay, ensuring complete data isolation between accounts. The SK Federation President has read-only access to aggregated data across tenants, while an audit log records actions across all roles. A public transparency dashboard presents only aggregated, read-only information to unauthenticated users. This design allows new barangays to be onboarded as tenants without separate deployments and keeps each council’s records isolated from the others.
\vspace{5mm}

\subsubsection{Target Users and Platform}
\label{subsubsec:target_users_and_platform}

\hspace*{\parindent}KABISIG is a responsive, web-based system accessible on desktop computers, laptops, tablets, and smartphones through a modern web browser, without requiring a native application installation. The system supports five user types across seven functional system actors within the SK governance hierarchy:

\begin{itemize}
    \item \textbf{Super Admin (SK Federation President):} Oversees all 27 barangays of Naga City as pre-provisioned tenants. Manages administrative linkages by issuing system invitation emails to SK Chairpersons, processes leadership transfers in cases of resignation, end of term, or succession by demoting the outgoing Chairperson and promoting the successor, views aggregated city-wide analytics (budget utilization, demographics, and program participation), and reviews the audit log across all roles. The Super Admin does not manage the day-to-day youth data of any individual barangay.
    \item \textbf{Barangay Admin (SK Chairperson):} Serves as the executive head of a single barangay’s SK Council, with access restricted to that barangay’s \texttt{tenant\_id}. Reviews pending youth registrations and uploaded IDs and approves or rejects them, sets the total annual SK budget in accordance with DILG JMC No. 1, s. 2025, reviews and approves resolutions, minutes, and liquidation reports submitted by the Secretary, oversees programs created by the Kagawad and the council’s inventory, and configures the official Facebook Page integration.
    \item \textbf{SK Officials (Kagawad, Secretary, Treasurer):} Operational council members who share a single role in the database, with their interfaces differentiated by position:
    \begin{itemize}
        \item \textbf{Kagawad (Program Officer):} Creates and schedules programs and events, tracks participant slots, scans youth QR codes for attendance using the device camera via \texttt{html5-qrcode} and \texttt{getUserMedia}, and reviews feedback.
        \item \textbf{Secretary:} Uploads and categorizes council documents, drafts resolutions, routes them to the Chairperson for approval, tracks compliance deadlines, and records official council attendance.
        \item \textbf{Treasurer:} Allocates program budgets from the total SK budget set by the Chairperson, records itemized expenses with automated VAT and non-VAT computations, tracks budget utilization, and manages the council’s inventory and assets.
    \end{itemize}
    \item \textbf{Youth Constituent:} A registered youth aged 15 to 30 who applies through the public portal and remains pending until approved by the SK Chairperson. Once verified, the youth receives a Digital Youth ID with a unique QR code and may register for programs. Youth Constituents can view only their own profile, public programs, and the transparency portal, and can submit feedback (optionally anonymous) through \textit{Boses ng Kabataan}.
    \item \textbf{Public Viewer:} An unauthenticated citizen who needs no account, invitation, or login credentials. Has read-only access to the Public Transparency Dashboard, budget summaries, program accomplishments, and announcements, in line with the DILG Full Public Disclosure (FPD) policy.
\end{itemize}

\subsection{System Development Life Cycle}
\label{subsec:system_development_life_cycle}

\hspace*{\parindent}The development of KABISIG follows the Agile Software Development Life Cycle, specifically utilizing the Scrum framework through short iterations in which requirements, design, development, testing, and review are repeated for each module. Agile and Scrum were chosen because the requirements of SK councils vary by role and may change as users see working features, and because the system’s functions can be delivered in logical increments. Modules were developed in the order of their functional dependencies: pre-provisioned multi-tenant configuration and role management, youth registration and verification, program management and QR attendance, budget and expense management, governance documents and resolutions, and federation analytics with the public transparency dashboard. After each sprint iteration, a working version was presented to representatives of the SK Federation, SK Chairpersons, and SK Officials, and their feedback was used to refine the module before the next iteration began. \subsection{Relevant Models and Theories}
\label{subsec:relevant_models_and_theories}

\hspace*{\parindent}The conceptual and empirical foundation of KABISIG is guided by established software evaluation standards, user acceptance constructs, governance principles, and technical architectures.

\subsubsection{Evaluation and Acceptance Frameworks}
\begin{itemize}
    \item \textbf{ISO/IEC 25010:2023 Software Quality Model:} Used to evaluate KABISIG against all nine product quality characteristics: functional suitability, performance efficiency, compatibility, usability, reliability, security, maintainability, portability, and safety. IT experts and technical evaluators rate the system on each characteristic.
    \item \textbf{Technology Acceptance Model (TAM):} Used to measure how SK officials and youth constituents accept the system through four core constructs: perceived usefulness, perceived ease of use, attitude toward use, and behavioral intention to use.
\end{itemize}

\subsubsection{Governance Foundation}
\begin{itemize}
    \item \textbf{Good Governance Theory:} Provides the governing principles of transparency, accountability, participation, and effectiveness. In KABISIG, these principles correspond directly to the public transparency dashboard (transparency), audit logs and approval workflows (accountability), \textit{Boses ng Kabataan} feedback and community polls (participation), and automated reporting and analytics (effectiveness).
\end{itemize}

\subsubsection{Technical Models}
\begin{itemize}
    \item \textbf{Multi-Tenant Architecture:} Allows the SK councils of the 27 barangays to share a single unified system while ensuring that each tenant’s records are securely isolated by \texttt{tenant\_id} via PostgreSQL Row-Level Security (RLS).
    \item \textbf{Role-Based Access Control (RBAC):} Restricts system access according to specific user roles. The operational interfaces of the SK Kagawad, SK Secretary, and SK Treasurer are further separated by position, and all sensitive actions are recorded in the system audit logs.
\end{itemize}
